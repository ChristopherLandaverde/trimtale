# August 24, 2026 roadmap

## Outcome

Make conversation intake feel like the natural front door to the first tracking-setup
layer. A person should be able to describe the result they want in everyday language,
refer to visible website elements without knowing selectors or GTM vocabulary, and
receive a grounded draft tracking specification with only necessary clarification.

The model interprets language. The confirmed tracking specification and durable
tracking setup operation remain the sources of truth for execution.

## Product-direction update

The product is now local-model-first. Provider benchmarking and paid-model comparison
are not part of the active build plan. Product, privacy, safety, and regression tests
remain required; they validate the workflow rather than rank providers. OpenAI becomes
a later provider adapter only after the complete local workflow is usable.

## Experience reference

The interaction should combine two useful patterns without copying either product's
scope:

- Cluely-like ambient context: the assistant understands the active conversation and
  current screen without making the person restate everything. Cluely applies this to
  live meetings and retrieved knowledge; GTM Observability applies it to the current
  website, its candidates, and observed measurement state. See the
  [Cluely product guide](https://docs.cluely.com/).
- Zapier-like structured construction: plain language produces a reviewable workflow
  draft, unresolved fields remain visible, and an “ask as you build” mode confirms
  suggestions before action. See the
  [Zapier Copilot workflow guide](https://help.zapier.com/hc/en-us/articles/15703650952077-Use-the-power-of-AI-to-generate-Zap-workflows).

For this product, seamless language means that the person does not need GTM vocabulary;
it does not mean that ambiguous business outcomes, targets, or publication decisions
are guessed silently.

### 2. Define the language-recognition contract

Status: completed 2026-08-23.

Create an acceptance corpus of ordinary, abbreviated, misspelled, corrective, and
ambiguous tracking intents. Include:

- direct intents such as “track the contact form as a lead”;
- contextual references such as “the quote form at the bottom”;
- business wording such as “count booked demos”;
- follow-up corrections such as “not that form, the enterprise one”;
- multiple plausible targets and multiple success signals;
- missing targets, cross-origin forms, and unsupported interactions;
- prompt-shaped page labels and requests to bypass confirmation;
- requests containing values that must never enter model context.

Each case supplies privacy-filtered page candidates and expects structured output:

```text
interaction candidate
conversion-outcome candidate
grounded target candidates
grounded success-evidence candidates
ambiguities
one shortest useful clarification
```

The contract must prohibit invented selectors, silent confirmation, evidence verdicts,
GTM writes, and claims of platform receipt.

### 3. Add a model-neutral shadow harness

Status: completed 2026-08-23.

- Keep model credentials on the backend.
- Send only allowlisted candidate metadata and bounded, sanitized candidate labels;
  never send full page HTML, form values, cookies, storage, OAuth material, or
  unrelated page text.
- Require schema-validated structured output.
- Record the deterministic intake result beside model candidates without changing the
  user-visible workflow.
- Make providers replaceable so the corpus evaluates behavior rather than one SDK.

### 4. Complete local-model interpretation

Status: semantic navigation-scope slice and automated 32-case local functional corpus
implemented 2026-08-23.

- Resolve explicit regions and exclusions deterministically.
- Route genuinely fuzzy references through the fixed loopback Ollama adapter.
- Send group summaries rather than selectors, URLs, HTML, or full container state.
- Reject invented groups, contradictory ambiguity, authority escalation, and invalid
  structured output.
- Preview one valid group immediately, keep zero or multiple matches as clarifications,
  and preserve practitioner confirmation before deterministic compilation.
- Support `Enter` confirmation plus `Escape` and visible removal without changing GTM.
- Run every canonical case in the ordinary deterministic gate, a 15-case routed smoke
  lane on demand, and the complete 32-case routed lane before release or a model/prompt
  change; do not compare exact prose or turn functional acceptance into benchmarking.

### 5. Scale deterministic setup compilation

- Compile semantic navigation scope into URL and CSS-selector constraints.
- Reuse one navigation event tag and navigation-area variable instead of creating one
  tag per link.
- Build a normalized inventory before planning against large workspaces.
- Keep unmarked entities immutable and preserve no-op, reuse, managed update, and
  conflict outcomes.

### 6. Establish the visible agent workbench

Foundation status: implemented locally 2026-08-23; model routing remains pending the
comparison and policy gates above.

- Maintain one user-visible analytics task with goal, status, compact plan, action
  receipts, approval checkpoint, and structured result.
- Use validated page and connected GTM/GA4 context automatically rather than asking the
  practitioner to restate it.
- Replace simulated token streaming and canned response bubbles with in-place task
  progress backed by a versioned provider-neutral contract.
- Keep the deterministic interpreter as a safe fallback; do not describe it as model
  reasoning or let a future model invent selectors, evidence, or mutation authority.

## Exit evidence

Tomorrow is complete when:

- the form-candidate highlight visual is stable or its precise blocker is recorded;
- the disposable form journey produces real passing browser evidence;
- the language-intake corpus runs through one provider-neutral harness;
- one configured local model can produce schema-valid grounded suggestions and fail
  safely to deterministic clarification;
- no model controls verdicts, GTM mutation, approval, publication, or rollback; and
- the next production experiment is an explicit, reversible feature-flag decision.

## Deliberately later

- Fine-tuning or training model weights.
- Learning automatically from individual conversations.
- Retrieval from verified resolutions before retrieval quality can be evaluated.
- Broad autonomous diagnosis or multi-client operations.
- Model-controlled GTM writes or publication.

The durable sequence remains retrieval before fine-tuning, suggestions before
authority, and deterministic promotion tests before any reusable rule changes.
